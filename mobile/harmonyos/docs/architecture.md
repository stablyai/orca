# Architecture

The native ArkTS shell renders the same desktop-delivered React mobile pages as the Android/iOS shell. Desktop and Expo runtime sources remain unchanged.

## Data flow

1. PairScan parses direct and relay offers, pins the desktop key, provisions relay credentials before the one-use ticket exchange and journals pairing state. Host metadata and personal preferences are distinct from credentials held in Asset Store.
2. HostSession creates a physical client for each attempt, advertises the shared mobile runtime capabilities, probes liveness, switches from direct to relay on failure and periodically tries direct upgrade. Relay outer authentication precedes pinned E2EE; resume is confirmed against desktop state. Credential rotation retains the pending request identity through an ambiguous result.
3. WebBundleFetcher validates paths, sizes and hashes. Cached generations are addressed by the complete manifest fingerprint, so two desktops cannot reuse different code under the same build ID. Missing cached assets invalidate the completion marker.
4. ShellScreen serves only manifest resources from the local origin with a CSP and a document-owned native bridge. BridgeHost bounds pending work, preserves executionHost, fragments large replies, translates terminal/screencast binary data and coordinates navigation/back/one-shot route params.
5. PageStorageStore overlays allowlisted global preferences onto host-scoped legacy page values. DeviceRowStore separately seals current cache/draft rows with an Asset Store key, binds host/table/key to ciphertext and commits each row by checked write, fsync and rename. Cache eviction never removes drafts.
6. NativeDevice owns staged handles, PDF/image actions, the PCM ring, a system speech recognizer and the microphone wake lock for one document. A native PasteButton grants access for the requested clipboard read. Pausing or disposing cancels pending clipboard/picker/recognizer/download work and restores the earlier wake-lock state.
7. AgentWatch reads the official notification stream (legacy fallback for older hosts). LocalNotifier checks permission, consent, delivery filters, sound and the visible target immediately before publication. Dismissal wins over an earlier asynchronous publish. Notification routes retain the pane and execution host.

## Rendering and compatibility

The Web component stays inside ArkUI's reserved system-bar area. ArkWeb resizes the layout and visual viewports for the keyboard; init does not add the keyboard height a second time. The shared page provides its terminal key row. Native controls use the mobile palette, Geist/Lucide assets and the mobile translation catalogs with platform-specific fallback descriptions.

Reconnect creates a new bridge generation and restores its route parameters. Mutating RPCs are not automatically replayed after a delivery-unknown timeout. Newer server features are negotiated; unsupported optional device capabilities are not advertised.

Fixed vectors generated by the pinned upstream client/contract prove the actual ArkTS direct/relay E2EE transcript, auth, text/binary sequencing and replay refusal. Published SHA/HMAC/HKDF vectors execute the actual hash implementation. This evidence does not replace live relay, remote desktop or device tests.

The official APNs/FCM gateway has no HarmonyOS registration/provider branch. Remote Huawei push requires upstream service support. Prototype diagnostic pages remain under pages/Spike*; they are not production acceptance evidence. AppGallery distribution and older HarmonyOS SDKs remain outside this API 26 build.
