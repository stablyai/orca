# iOS alignment and verification

The source reference is the iOS client at stablyai/orca commit `12e809c7556e49bb513b9f009695a9523c088a9e`, together with the desktop mobile-web bundle and shared RPC contracts in this contribution. Home, new-workspace and the settings menu retain that reference implementation. Shared code changes elsewhere are part of the contribution and need iOS/Android review. HarmonyOS uses system camera, permission, photo, share and PDF interfaces for the corresponding iOS flows.

## Verification status

The implementation and local evidence below were reviewed on 2026-11-11 at `da2ee8034`. They support a Draft PR, with the acceptance gaps stated here. They do not prove complete iOS product parity. A conflict-free merge preview against upstream `60d7605df` is integration evidence only; that upstream tree was not the source baseline for these builds.

The following capability and release boundaries remain explicit:

- Terminated-app push requires the official gateway to accept a HarmonyOS provider. It currently accepts APNs/FCM registrations only, and the available gateway cannot be changed or deployed by this contribution. Connected-app notifications do not close this gap.
- AppGallery application identity, release signing and push provisioning need a maintainer-owned Huawei project. The example bundle and local development provisioning are test configuration, not a transfer of production ownership to a contributor.
- The current package requires HarmonyOS 7 / API 26. It does not provide HarmonyOS 5/6 compatibility or AppGallery release/update distribution.
- System on-device speech recognition currently supports offline Mandarin. The paired-computer path remains available where configured; this does not establish parity with every iOS on-device language.
- Native common labels use all eleven shared mobile locale catalogs. HarmonyOS-specific descriptions still fall back to English outside Simplified Chinese.

Use the [device checklist](device-testing.md) to record the missing acceptance. HarmonyOS-specific enhancements beyond this iOS alignment remain subject to product approval.

## Interpretation

The generated Home presentation adapter reuses Orca's shared automation schedule descriptor, terminal agent names and quota reset countdown. The HarmonyOS adapter supplies the same UTF-8 length check through ArkTS encoding.

Use the [device checklist](device-testing.md) for device acceptance. A physical API 26 phone paired to an isolated Orca 1.4.251 runtime, opened a folder workspace and terminal, sent an ASCII command, and recovered after the USB forwarding rule was restored. A separate run opened terminal settings, the workspace page and network diagnostics without adding a desktop authentication event. Diagnostics also recorded successful reuse of the pre-rendered document. The official Relay and device-specific flows in the checklist require separate runs. Fixed E2EE vectors exercise the actual cryptographic code.

The Agents list keeps local and SSH workspaces separate when their raw workspace IDs collide. The shared desktop session inventory and terminal subscriptions still key sessions by the raw workspace ID, so ambiguous rows stay visible and block pane navigation. Read and clear changes follow the workspace's known runtime owner. A write needs a desktop window on that runtime and skips rows with ambiguous or stale ownership.

The official gateway limitation prevents terminated-app notification parity. The maintainer-owned AppGallery Connect project, app identity, signing and Huawei Push Kit credentials belong to the production release. The source defaults to an example bundle ID for the emulator. A signed debug package uses the local developer's provisioned bundle ID and supports online notifications.
