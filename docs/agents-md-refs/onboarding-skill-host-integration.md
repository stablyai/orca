# Onboarding skill host integration

The onboarding Chat UI branch must integrate its provider-specific setup with the workspace skill runtime before landing. The Chat UI preference chooses a launch surface; it does not establish where a workspace agent runs.

- For workspace setup, retain `useActiveProjectSkillRuntime()` for install, discovery, WSL command and disabled-reason fields. Pass its `discoveryRuntimeTarget` to every discovery hook and its `bundledSkillTarget` to planning and installation. Never replace these with the local host because the Chat UI preference or local catalog is enabled. Direct SSH without a serving Orca server remains unsupported for bundled installs; WSL uses the existing terminal path. Paired servers own their own disk and older servers must retain the existing unsupported/update behavior.
- Local floating chat is a separate explicit scope. Only use local discovery and local installation when the surface is actually setting up that local chat, and label that scope in the existing UI. Do not infer it from the global preference. For workspace launches, use `resolveAgentLaunchRoute` and its host-specific capability and catalog inputs when choosing provider-specific behavior; do not duplicate its feasibility rules. Preserve terminal fallback and its provider roots.
- The branch's current local-only `target.agent` plan request cannot select a provider on paired servers. Extend the server protocol with capability negotiation before claiming provider-specific remote coverage; old hosts must receive a compatible request or a visible update-required state, never a local fallback. Discovery and installation must use the same host and provider semantics.
- Treat blank or null default agent as an explicit no-agent state, with a control that returns to agent selection or opens the existing agent settings. While ownership or host capabilities are unknown, show checking rather than installed or absent. When a selected agent cannot be installed or scanned, show a specific unsupported state and a recovery action. Derive these states from the existing selection and resolution; do not synchronize additional booleans.
- Add integration coverage through real launch/ownership resolution and discovery/install boundaries for local, WSL, SSH, paired and folder workspaces, including mismatched local and remote inventories, blank agent recovery, pending ownership, and older servers. Verify the explicit floating scope separately and run hidden/background validation.

The main-based change accompanying this note aligns capability and setup-guide discovery with the active workspace owner. It does not implement the branch's provider-specific filtering or its no-agent recovery UI; those depend on the uncommitted onboarding changes and must be completed and tested there.
