# Feature map

| Flow                                                             | Entry point                                                                        | Runtime and data                                                                                                                                                                                                                                                                                                                                                                                                         | Verification                                                                                                    |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| Bot hands a task to another bot                                  | `orca orchestration send --to bot:<name> --type handoff`                           | [Bot request admission](../../src/main/runtime/rpc/methods/orchestration/messaging/bot-request-send.ts) stores the mail and its request record. The [request view](../../src/main/bots/bot-request-view.ts) shows how to handle and answer it.                                                                                                                                                                           | `pnpm check:changed`                                                                                            |
| Bot starts a supervised worker                                   | `orca orchestration worker-start` and `--on` for a paired computer                 | [Worker start](../../src/main/runtime/rpc/methods/orchestration/worker/worker-start-method.ts) resolves placement and bot lineage. The [Dispatch transaction](../../src/main/runtime/orchestration/db/worker-dispatch/worker-dispatch-start.ts) checks capacity and records the start in SQLite.                                                                                                                         | [Capacity invariant](../../src/main/runtime/orchestration/db/worker-dispatch/bot-run-worker-capacity.test.ts)   |
| Structured worker starts in the calling bot's own home           | `orca orchestration worker-start --worktree current --agent <agent>`               | [Worker placement](../../src/main/runtime/rpc/methods/orchestration/worker/start/placement/worker-placement-topology.ts) seeds the matching chat provider's permission mode, with the bot's default as a fallback. The [session wiring](../../src/main/bots/bot-structured-session-wiring.ts) loads the bot home's instructions and linked skills. Other workspaces and terminal launches use their own launch settings. | `pnpm check:changed`                                                                                            |
| Bot hands an incoming request to a fresh local structured worker | `orca orchestration worker-start` during a direct bot handoff, with the same agent | [Worker handoff brief](../../src/main/runtime/rpc/methods/orchestration/worker/start/worker-handoff-brief.ts) checks the active journal opener and stored recipient before quoting a bounded portion of the admitted handoff in the worker's first task.                                                                                                                                                                 | [Handoff invariant](../../src/main/runtime/rpc/methods/orchestration/worker/start/worker-handoff-brief.test.ts) |
