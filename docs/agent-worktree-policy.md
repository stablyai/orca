# Baseline selection and agent worktree guidance

The New Workspace composer requires a selected starting ref for Git projects. It labels the existing picker as **Baseline (required)**, disables ordinary creation until a selection exists, and validates again on submission. Branch and PR/MR selections carry their own starting ref. Choosing the project default records its concrete ref instead of an empty fallback. Direct task launches without a baseline open the composer first. Folder workspaces do not require a Git baseline.

When refreshing a remote tracking ref fails, the desktop creation path and the runtime's cached-ref refresh stop before adding the worktree. A locally cached tracking ref is not proof that the remote was refreshed. Explicit local refs and review commits keep their existing semantics. The runtime's explicitly requested local-fallback API remains available; this is not a blanket removal of local-only Git support.

`src/shared/agent-launch/policy/agent-worktree-policy.ts` owns the agent instructions. They cover baseline verification, task isolation, dependency installation, tests, paired repositories, integration, deployment authorization, reporting and safe cleanup. The selected starting ref accompanies the task at workspace creation. Existing-workspace launches use the stored base ref when available and otherwise tell the agent to obtain an explicit baseline.

Instructions travel with the initial task prompt through the existing terminal and structured-session delivery paths. The New Workspace composer, direct work-item launches, folder-workspace composer, prompted new-tab launches and host launch executor share the same text. A marked block is retained when the client and host both prepare the same launch. Drafts remain drafts; a reused terminal conversation and a promptless existing-workspace launch are unchanged. A new workspace created with an agent but no task supplies the instructions and tells the agent to wait for a task.

This is agent guidance, not a permission system or a guarantee of agent compliance. It does not rewrite a target project's AGENTS.md, CLAUDE.md or Git settings. Existing empty sessions do not gain the guidance retroactively. Worktree paths and branch naming still use Orca's project settings; the guidance tells agents how to create additional task worktrees and to verify/reuse the worktree Orca provided. Review heads are not treated as evidence of an integration baseline.

No new wire fields are required: older execution hosts can carry the instruction text using existing prompt delivery. Host-side refresh behavior changes only after that host is updated. SSH operations and verification belong to the execution host; an unreachable host never proves that a process exited.

Focused regressions cover missing/blank baselines, prompt idempotence, caller immutability, draft delivery, reused/floating terminals, and failed refresh of a cached remote ref. The `CreateFromPicker` fixtures show the required selection and explicit default choice in both themes. Run tests with `ORCA_BACKGROUND_LAUNCH=1`. Full rendered app validation must follow the repository's Electron skill and hidden Playwright CDP requirements.
