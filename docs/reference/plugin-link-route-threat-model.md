# Plugin link route threat model

Status: implementation baseline for security review. This document does not constitute security
approval. The contribution point itself is described in
[`plugin-link-routes.md`](./plugin-link-routes.md).

## Scope and trust model

This model covers `contributes.linkRoutes`: manifest validation, the public-suffix floor, consent,
the approved route table in main, its projection to the desktop renderer, and destination selection
at click time in the terminal and native chat surfaces.

A plugin is code from its author, and a link route is a standing instruction to send some of the
user's clicks somewhere other than where the user's own setting would send them. The route is
declarative — it names a hostname and a destination and nothing else — but its effect is permanent
behavior, granted by one dialog. That asymmetry is the core of this model.

Web and serve clients are out of scope by construction: they have no plugins bridge, so no route
ever reaches them. Mobile has no link-destination logic. Neither is defended; neither is reachable.

## Protected assets

- The destination of a user's click: which browser session, with which cookies, receives a URL.
- Orca's built-in browser session and any credentials it holds.
- Credential-bearing URLs (userinfo, tokens in query or fragment) passing through a clicked link.
- The remote-execution boundary: an SSH-owned or runtime-owned link must not be promoted into a
  local Orca browser tab.
- The truthfulness of the consent dialog's trust-tier copy.
- Renderer responsiveness on hover and click.

## Actors and boundaries

Actors: a plugin author who over-claims, two plugin authors who claim the same host, a malicious
plugin author whose plugin is later kill-listed, a compromised renderer, and an attacker who
controls a hostname that a legitimate route's wildcard happens to cover.

Trust boundaries:

1. Manifest text to the validated `PluginManifest` (shared Zod shape rules).
2. Validated pattern to the approved table (main: consent state + public-suffix policy).
3. Main's approved table to the renderer store, over `plugins:listLinkRoutes`.
4. Renderer store to a destination decision, at click time, inside `httpLinkActionDestinationsFor`.

## Security invariants

- `canSourceOwnerOpenInOrca` is evaluated before route matching, always.
- No RegExp is ever constructed from manifest text.
- A wildcard never crosses a dot except in a mid-label pattern confined to a reserved TLD.
- A wildcard tail is never a public suffix, private suffixes included.
- Only approved, conflict-free routes cross the IPC boundary.
- A credential-bearing URL is never matched.
- An IP literal is never matched.
- A route match always supplies both `primary` and `alternate`.
- Route lookup is synchronous and never runs on hover.
- An empty table behaves exactly as no plugin routes at all.

## Threat register

| ID    | Threat                                                                                                                                                        | Controls and evidence                                                                                                                                                                                                                                                                                                                                                                                  | Residual                                                                                                                                                                                                                                                              |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| LR-01 | A plugin claims an over-broad namespace (`*.com`, `*.github.io`, `*.s3.amazonaws.com`) and captures traffic it has no relationship to.                        | `routePatternViolatesSuffixPolicy` rejects any wildcard whose tail is a public suffix, with `allowPrivateDomains: true` so private suffixes count. A violation rejects the whole plugin at discovery and at install staging, before consent.                                                                                                                                                           | A user can still approve a plugin claiming a whole domain the author does control; consent copy is the only control there.                                                                                                                                            |
| LR-02 | A dot-crossing wildcard defeats the suffix check and reaches another tenant — `*.amazonaws.com` → `victim-bucket.s3.amazonaws.com`.                           | `kind: 'label'` matching requires a non-empty prefix containing no dot. Covered by matching tests.                                                                                                                                                                                                                                                                                                     | None known.                                                                                                                                                                                                                                                           |
| LR-03 | A mid-label wildcard against a real TLD captures unrelated registrable domains — `*e.com` → google.com, apple.com, stripe.com.                                | Mid-label patterns are accepted only when the final label is an RFC 6761 / RFC 2606 reserved name, which can never be publicly registered, and the literal prefix must be ≥ 6 characters.                                                                                                                                                                                                              | A mid-label route can still cover an entire reserved-TLD dev namespace belonging to another tool on the same machine. Accepted: reserved TLDs are not routable.                                                                                                       |
| LR-04 | Two plugins claim the same hostname and the winner depends on install order, or a new plugin steals an approved plugin's host.                                | A contested hostname is dropped from the active table entirely — neither plugin wins — and annotated with a `conflict` string on each declared route, rendered at consent. A conflict is never an activation error, so it cannot be used to disable a rival plugin's unrelated routes.                                                                                                                 | Silent no-op for both plugins after approval; the post-approval surface showing which host is contested is the consent dialog only.                                                                                                                                   |
| LR-05 | A route promotes an SSH-owned or runtime-owned link into a local Orca browser tab the source host cannot reach.                                               | `canSourceOwnerOpenInOrca` runs first in `httpLinkActionDestinationsFor`; a route is consulted only after it passes. Pinned by a dedicated test asserting `{ primary: 'system' }` with no `alternate` for a non-Orca-capable owner even with a matching `orca-browser` route.                                                                                                                          | This is the single most important invariant; it lives in one function and is enforced by test, not by types.                                                                                                                                                          |
| LR-06 | A credential-bearing URL is re-homed into the built-in browser session, which may hold real cookies.                                                          | `matchLinkRoute` returns null when `username` or `password` is non-empty.                                                                                                                                                                                                                                                                                                                              | **Accepted residual.** Tokens in the query string or fragment — the far more common shape today — are not covered. Refusing them would require guessing which parameters are secrets. A routed link can therefore carry a bearer token into the Orca browser session. |
| LR-07 | Homograph / IDN confusables: a pattern or a clicked host in a lookalike script matches something the user did not intend.                                     | Both sides are canonicalized through the URL parser (IDNA/UTS-46) to punycode **before** case folding — folding first diverges from the browser for Greek final sigma. Pattern and host are therefore compared as the same ASCII string the browser resolves.                                                                                                                                          | Confusable _registrable domains_ (`xn--` lookalikes) are outside Orca's ability to judge; the user sees the ASCII form at consent.                                                                                                                                    |
| LR-08 | `https://real.example.com@attacker.test/` is read as `real.example.com` by the user and matched as such.                                                      | Matching uses `URL.hostname`, so userinfo never participates. Patterns reject `@` outright (`FORBIDDEN_PATTERN_CHARS`). LR-06's userinfo refusal also declines the match entirely.                                                                                                                                                                                                                     | None known.                                                                                                                                                                                                                                                           |
| LR-09 | IP literal or trailing-dot spellings evade or satisfy a route — `127.1`, `2130706433`, `0x7f.1`, `example.com.`                                               | `normalizeHostForMatch` strips a trailing dot on both sides and returns null for anything the URL parser canonicalizes into a dotted quad or bracketed IPv6, so an IP literal can never satisfy any route. Empty labels and over-length hosts are rejected.                                                                                                                                            | None known.                                                                                                                                                                                                                                                           |
| LR-10 | A hostile pattern causes catastrophic regex backtracking on every click or hover.                                                                             | Impossible by construction: no RegExp is built from manifest text. Matching is `endsWith` plus a dot scan over labels. The fixed regexes in the module are LDH label shape checks over ≤ 63-character inputs.                                                                                                                                                                                          | None.                                                                                                                                                                                                                                                                 |
| LR-11 | A kill-listed or revoked plugin keeps redirecting clicks because the renderer cached its table.                                                               | Kill-list arrival, consent revoke, disable and uninstall all funnel into `performActivationStateReconciliation()` → `notifyChanged(true)`; the renderer store refetches on that event and latches `loaded` even on failure. Read from main's code, not pinned by an end-to-end revocation test — see the gap below.                                                                                                     | A click in flight during revocation uses the old table.                                                                                                                                                                                                               |
| LR-12 | A truncated URL is matched. WebLinksAddon reports a physical-row match, cut at hard wraps, and a URL cut mid-authority can present a different host entirely. | Destinations are computed from the logical hit-test's complete URL, not from the addon's `url` parameter. Pinned by a hard-wrapped-URL test.                                                                                                                                                                                                                                                           | None known; the getter shape is what prevents regressing to eager computation with no URL in scope.                                                                                                                                                                   |
| LR-13 | A route-only plugin is presented to the user as harmless.                                                                                                     | Consent's `hasInstructionalContent` counts `linkRoutes`, so a route-only plugin no longer shows "Declarative content — no plugin code", and the marketplace preview enumerates link routes rather than showing "Manifest metadata only". Consent copy lives in a `Plugin`-prefixed component, which the language-pack protection covers by prefix, so a plugin-supplied translation cannot rewrite it. | Trust-tier wording has not been through a copy review.                                                                                                                                                                                                                |
| LR-14 | A compromised renderer sends an unapproved route table into the decision path.                                                                                | The renderer only _reads_ routes; the approved table is built in main from consent state and re-checked against the suffix policy before publication. There is no renderer→main write path for routes.                                                                                                                                                                                                 | A compromised renderer can of course open any URL directly; link routes add no new authority there.                                                                                                                                                                   |
| LR-15 | Route activation and consent are unauditable after the fact.                                                                                                  | None. The plugin subsystem has no audit log today for consent, kill, or activation.                                                                                                                                                                                                                                                                                                                    | **Accepted for this phase.** Adding a logger for link routes alone would be misleading precision.                                                                                                                                                                     |

## Required review evidence

- Matching unit tests: both wildcard forms, dot-crossing rejection, reserved-TLD restriction,
  IDNA-before-folding, IP literals, trailing dot, userinfo, empty table.
- Suffix-policy tests against real public and private suffixes.
- Registry tests: approval filtering, contested hostnames, rank determinism, wholesale rebuild.
- The gate-order test (LR-05) and the truncated-URL test (LR-12).
- **Gap:** there is no end-to-end revocation test from kill-list arrival to an emptied renderer table. Main's reconciliation and the store's refetch are each covered in isolation; the seam between them is not.

Accepted residual risks — LR-06 (tokens in query/fragment), LR-15 (no audit log) — are recorded
here deliberately and should be re-examined if link routes ever gain a non-http scheme, redirect
following, or a per-project scope.
