# Official DSH session history

Orca discovers official DeepSeek Harness persistence in `$DSH_HOME/sessions` (default `~/.dsh/sessions`) independently of hooks: the official Claude-compatible hooks emit an empty `transcript_path`. The source is the execution host's home and environment. Native discovery uses existing WSL home roots/read gates; SSH and relay readers use host paths and host byte streams, never the desktop's home.

Schema evidence is [deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness/tree/639ed015397290b3745d163aafe02ffee4aa3f84), official CLI `@deepseek-ai/dsh@0.2.0-rc.2`. Relevant sources are `packages/session/session-persistence-jsonl/src/{format,index,zstd}.ts` and the `session-format-v0-to-v1`, `v1-to-v2`, `v2-to-v3`, `v3-to-v4` codec packages. These were inspected, not copied into Orca. The transcript fixture is a sanitized actual official CLI capture against an isolated endpoint rejecting model requests with HTTP 401; it contains no generated assistant response or successful paid generation.

## Generations and messages

A session lives at `<home>/sessions/<project>/<session>/session.jsonl` (v0), or `session.vN.jsonl`, optionally suffixed `.zstd`. Discovery selects the highest canonical numeric generation before applying the recency limit and never decodes old generations to choose one. Leading-zero, temporary and projection-cache filenames are excluded. Conflicting compressed/uncompressed generations are reported and withheld. Versions 0–4 are supported in this session-owned layout; obsolete flat files are not offered for resume because current official DSH rejects them.

The header supplies the session id, cwd, creation time, delegation depth, origin and seed metadata. Delegated children (`origin: subagent` or positive depth) are excluded from top-level history. A parent link alone does not exclude an independent fork. V0/v1 `seedLength` and the **last** v2+ inherited `session/end-seed` boundary exclude inherited prompts from the fork's own conversation. Seeded sources are streamed twice on their execution host to locate that final cut before emitting any preview/search message; no inherited text is buffered. A changed cut fails the read. Released packed deltas consume sequence slots without becoming duplicate assistant messages. Missing seed boundaries, invalid ownership metadata and sequence gaps are contained scan failures.

Only settled `user/message` events with source kind `user`, settled `assistant/message`, and tool results reach the existing transcript consumer/accumulator. V0 flat pre-identity payloads and v0–v3 user-role tool-result wrappers are normalized to conversation/tool roles; v4 uses first-class tool messages. System/injected context, attempts and deltas do not inflate conversation count or search. Model, title, timeline and token usage come from persisted events. Folder workspaces need no Git repository.

## Compression and bounds

DSH appends independently checksummed Zstandard frames. Node's synchronous and streaming Zstandard decoder stops at the first frame, so Orca locates each standard frame and runs the native decoder once per frame. Native checksums are validated. A frame is capped at 32 MiB compressed, 64 MiB decoded and a 64 MiB decoder window; each JSONL record uses the existing 10 MiB transcript limit. The scanner streams the latest generation, retaining only the existing bounded preview/consumer state. Appends and rewrites reparse this source through the existing cache channel rather than introducing another history store.

A torn plaintext final record is withheld until its newline arrives. Truncated or corrupt compressed frames fail the read rather than publishing an apparently complete prefix; no fallback to an older generation occurs. Unsupported future formats and runtimes lacking `createZstdDecompress` report an update requirement. Actual Electron 43.7.5 / Node 24.21.0 decoded the untouched upstream-generated capture. Older hosts lacking transcript byte reads cannot substitute a text RPC or a client-local read. The production relay byte reader permits compressed input only for an explicit host-internal `dsh-zstd` mode, a canonical DSH source path and matching frame magic; unrelated text transcript binary rejection remains enabled. This adds no wire operation.

## Open log, export and resume

View Log preserves the compressed source path in a read-only JSON editor tab. The optional `fs.readFile.decodeDshHistory` request asks the owning host for decoded JSONL; the optional `decodedDshHistory` response confirms it. SSH clients reject responses without that marker, so old hosts cannot pass binary bytes as decoded text. Local exact-path authorization still runs before decoding. SSH logs require a workspace on that same host and keep an explicit SSH file-owner stamp. Generic runtime external logs remain unavailable rather than falling back locally.

The editor path menu's **Export decoded DSH log…** uses the existing `saveDownloadedFile` flow to save UTF-8 `<generation>.decoded.jsonl`. This never overwrites the compressed source. Open/export refuses sources over 32 MiB or decoded snapshots over 2 MiB instead of silently truncating an export. Compressed snapshots do not arm raw-byte live tailing; refresh reopens the bounded snapshot.

Resume runs `dsh-tui --resume <exact persisted id>` with the source's `DSH_HOME`, quoted through existing target-shell builders. WSL UNC source paths become Linux paths before home selection; host-published SSH commands retain host syntax. `dsh-tui` 0.12.0 is a community TUI over the official harness, not an official TUI binary. The official CLI remains responsible for rejecting ambiguous duplicate session ids or incompatible root encodings. Deletion stays unsupported: deleting one generation would leave older generations, projection caches and fork/delegation links sharing that identity.

## Independent versions

List decoders already discard unknown agent rows while preserving known rows. Search requires an explicit opt-in because old search response schemas reject an unknown agent. New clients send optional `includeDshHistory`; new hosts publish optional `dshHistory` in status. A new client removes DSH filters for an old host (DSH-only searches return empty); a new relay host filters DSH out before pagination for old clients. No stream opcode or existing RPC method changed.

Native macOS and the actual binary/UI flow were exercised. Windows command forms, WSL addresses/read seams, SSH provider/relay frames, byte absence, old-host responses and permission/budget failures are automated contracts, not claims of a live Windows or SSH subscription run. Successful paid generation, real tools/approval/Stop, Reasonix, DeepSeek Build and desktop/mobile balance are separate follow-ups.

Codec regression provenance: the task-owned published `@deepseek-ai/dsh-session-format-v0-to-v1` through `v3-to-v4` packages at `0.2.0-rc.2` validated the committed `dsh-codec-v0` through `v4` fixtures with their real decoders; v2–v4 fixtures also used their real encoders. Their human/tool text is explicitly synthetic, not paid generation. Multi-marker attribution and pre-identity v0 payload tests follow the pinned codec/migration sources.
