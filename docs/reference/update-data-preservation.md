# Update profile recovery

**Behavior:** Explicit desktop and supervised-server updates save credentials, checkpoint the profile store, and complete a private profile snapshot before starting installation. A failed preservation step aborts the install. Ordinary application exit no longer silently installs a downloaded update.
**Storage:** `src/main/update-profile-snapshot.ts` copies durable profile files and empty directories. `update-sqlite-snapshot.ts` uses the existing online SQLite snapshot API, retaining committed WAL transactions. Locked Chromium databases are recovered only from a stable private capture; changed files abort the backup. Rebuilt browser caches, logs and process rendezvous files are excluded.
**Recovery:** `update-profile-restore.ts` validates manifest paths and SHA-256 checksums before creating a new destination. It refuses existing destinations, duplicates, traversal and link ancestors. It never replaces the current profile or resets a database. Links are recreated last and can still point to resources outside the profile; those resources are not copied.
**Commands:** With the application stopped, run `pnpm exec tsx config/scripts/update-profile-snapshot.ts backup <profile> <backup-root>` and `pnpm exec tsx config/scripts/update-profile-snapshot.ts restore <backup> <new-profile>`. Start the appropriate Orca version with `ORCA_USER_DATA_PATH` pointing to the restored directory. Keep the original profile until the recovered version has been checked. Backups must remain private because they include credentials.
**Scope:** This protects the explicit built-in updater. It cannot intercept an installer launched independently, a package-manager upgrade, or writes in project folders or external agent homes. Databases are individually consistent; this does not create a distributed transaction across external services. Backups require room for a new profile copy. After completion, retain the new backup and the newest previous completed backup; only recognized backup directories are pruned. Failed copies remove their own staging directory, never another unfinished backup.
**Regression matrix:** `update-profile-snapshot.test.ts` covers WAL records, settings/history/documents, locked databases, empty directories, corruption, long paths and rejected destinations. `update-restart-preservation.test.ts` covers ordering and propagation of credential/backup errors. `updater.headless-serve-install.test.ts` and `updater.linux-root-package-install.test.ts` cover install-mode policy. `tests/e2e/update-profile-recovery.spec.ts` starts a hidden Electron app, saves real settings, closes it, restores its disposable profile to a new directory, and starts the recovered app. No production profile is used.
**Previous coverage gap:** Updater tests previously checked restart handoff without requiring a complete profile backup, and the first snapshot implementation omitted empty directories. Changes to preservation, restore or install policy must run the named cases. Platform-conditional cases are not treated as passed on another platform; OS installer replacement remains a separate release validation.

**Review regressions:** Windows link-ancestor comparisons now use the same case normalization as duplicate detection; the previous test covered only identical case. POSIX colon filenames remain valid. Known Chromium partition caches are excluded before filesystem reads; user folders named Cache remain durable and any unclassified file disappearing still aborts preservation. Snapshot tests cover case aliases, partition cache scope and two-backup retention. Hidden recovery tests stop isolated daemons before renaming and remove the renamed profile.
