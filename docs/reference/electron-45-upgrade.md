# Electron 43 → 45 upgrade review

Reviewed on 2026-10-22 against:

- [Electron 44 announcement](https://www.electronjs.org/blog/electron-44-0) and [44.0.0 release notes](https://github.com/electron/electron/releases/tag/v44.0.0).
- [Electron 45 announcement](https://www.electronjs.org/blog/electron-45-0) and [45.0.0 release notes](https://github.com/electron/electron/releases/tag/v45.0.0).
- [Versioned breaking changes](https://github.com/electron/electron/blob/v45.0.0/docs/breaking-changes.md), [clipboard API](https://github.com/electron/electron/blob/v45.0.0/docs/api/clipboard.md), and [safeStorage API](https://github.com/electron/electron/blob/v45.0.0/docs/api/safe-storage.md).

## Runtime and platform requirements

The desktop moves from 43.7.8 to **45.0.0**: Chromium 156.0.8078.48, V8 15.6, and embedded Node 24.22.0. The separate managed Node runtime stays at 24.22.1 with its existing verified assets and N-API 10. Its Electron association is updated; this upgrade does not replace remote-host binaries or change the wire protocol.

**macOS 13 (Ventura) is now required.** Electron 44 dropped Monterey. The builder minimum and desktop installation instructions explicitly reflect this. The separate macOS terminal host still has its own 13.5 floor and fallback policy.

Electron no longer publishes Windows ia32 or Linux armv7l builds. Orca's desktop targets are already x64/arm64. Electron 44 also updated its Linux support policy to supported major distributions; that documentation change does not justify raising Orca's existing glibc 2.31 native-module packaging gate. Linux/Windows packaging and runtime validation remain necessary in CI.

## Changes made

| Release change                                                                                                          | Orca adaptation                                                                                                                                                                                                                                                                                                    |
| ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 44: asynchronous clipboard, MIME-based `ClipboardItem`, removed image/raw-format helpers                                | Await reads and writes; use `ClipboardItem`/`Blob` for image and native-format data. Keep sender authorization, text/image limits, JPEG-under-`public.png` recovery, Windows copied-image fallback, and remote attachment/upload routing. Check source bytes and declared dimensions before native image decoding. |
| 44: `text/uri-list` maps to native file references                                                                      | Read canonical file lists on every platform before raw fallbacks; decode Windows drive/UNC URLs with Windows path semantics. Retain the single-file and ordinary-path checks for Windows image-file reads.                                                                                                         |
| 44: Linux selection moves to `clipboard.selection`                                                                      | Use the namespace only on Linux; return empty/no-op on other platforms.                                                                                                                                                                                                                                            |
| Async clipboard completion                                                                                              | Serialize text writes and read-back verification in the existing bounded publisher queue. Await diagnostic/recovery copies and native file writes so failures cannot masquerade as success. Keep the Wayland publisher workaround.                                                                                 |
| 44: per-WebContents zoom modes                                                                                          | Set browser guests to `isolated`, while retaining Orca's per-site/profile zoom persistence and explicit propagation to matching tabs. Browser reload/reset tests exercise the existing behavior.                                                                                                                   |
| 44: `select-client-certificate` can have null `webContents`; background net calls can automatically select certificates | Decline automatic certificate selection for background requests. Preserve existing browser-window handling. This prevents icon/download/backend requests from silently presenting the user's first matching certificate.                                                                                           |
| 45: removed sandboxed-preload `Buffer` global                                                                           | Send dictation samples as a `Uint8Array` byte view. The main process reconstructs the `Float32Array` from those bytes. A real sandboxed-preload test verifies sample values, a subarray offset, rate, and session.                                                                                                 |
| 45: Windows Error Reporting helper                                                                                      | Ensure `electron_wer.dll` is renamed to `Orca_wer.dll` alongside the executable, accepting a builder that already renamed it and failing packaging if absent. Existing `crashReporter.start()` enables capture; uploads remain disabled.                                                                           |
| 45: child launch failure `systemErrorCode`                                                                              | Include the new OS error code in existing child-process crash details.                                                                                                                                                                                                                                             |

Clipboard IPC channel names and results remain compatible with existing preload/web/mobile callers. Local clipboard access stays local, including when the target workspace belongs to a remote host. Git worktrees and folder workspaces use the same handlers.

## Deprecation requiring follow-up before Electron 46

Synchronous `safeStorage.isEncryptionAvailable()`, `encryptString()`, and `decryptString()` still work in 45 but are **removed in 46**. They remain behind `guardedSafeStorage` and the synchronous `SecretStore` contract. Callers include persisted host credentials, plugin secrets, and cloud profile sessions.

Migrate the shared secret-store interface and all callers together to `isAsyncEncryptionAvailable()`, `encryptStringAsync()`, and `decryptStringAsync()`. The latter returns `{ result, shouldReEncrypt, isTemporarilyUnavailable }`, not a string. Required checks for that follow-up:

- Read existing synchronous ciphertext on macOS, Windows, and Linux; preserve stored credentials and the plaintext fallback policy.
- Preserve the run-wide keychain withhold and headless-serve behavior. Async native calls do not by themselves prove there will be no OS prompt.
- Handle temporary unavailability without overwriting or discarding saved credentials; plan key rotation and durable re-encryption.
- Cover concurrent saves, startup hydration, plugins/profile sessions, and plain-Node hosts. Clients and remote servers update independently.

This upgrade deliberately leaves that shared persistence migration separate from the required clipboard/preload changes; do not bump to Electron 46 before completing it.

## Validation

Local validation uses macOS arm64 with hidden/background Electron windows and isolated test profiles. Tests never record microphone audio or overwrite the developer's clipboard. Automated coverage includes dictation byte transport, JPEG clipboard recovery and PNG previews, file-list parsing across platform formats, clipboard limits and concurrent write verification, remote attachment/upload routes, browser zoom/reload/popup behavior, fresh-profile startup, and terminal file-link/external-edit flows.

Run the regular desktop typecheck, focused unit tests, changed-code-quality gate, E2E type-error ratchet, and desktop build. The broad E2E typecheck has a grandfathered baseline and optional cloud/mobile dependencies; the ratchet is the regression gate. Windows WER loading, Explorer paste, packaged ASAR behavior, Linux Wayland/X11, GPU/WebGL, and native OS prompts require the corresponding platform CI or isolated-display tests. macOS source tests alone do not establish those results.
