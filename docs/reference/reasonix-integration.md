# Stable Reasonix integration

Orca supports the esengine Reasonix 1.x CLI as `reasonix`. The verified release is npm `reasonix@1.39.7`, source tag `v1.39.7` at [`6dbabcbf7135c56ff5186b0cd36f5cc2725f47b4`](https://github.com/esengine/DeepSeek-Reasonix/tree/6dbabcbf7135c56ff5186b0cd36f5cc2725f47b4). The npm manifest's `gitHead` and `reasonixCandidateSha` match that source. The default upstream branch develops Studio 2.x and does not establish the stable CLI contract. Reasonix remains a separate agent identity from DeepSeek Harness and DeepSeek Build.

## Install, launch and options

The official package is `reasonix`, whose `bin/reasonix.js` wrapper selects an optional `@reasonix/cli-<platform>-<arch>` native executable. Install the verified CLI with `npm install --global reasonix@1.39.7`, or use a private npm prefix for a controlled probe. Orca's agent catalog links to the pinned release and uses its existing execution-host executable discovery. Native executable identity and the exact npm entrypoint identify the process; an unrelated script named `reasonix.js` does not.

Bare `reasonix`, `chat` and `code` are interactive. `-p`/`--print`, `run`, `serve`, `web`, `acp`, machine queries and configuration commands do not own an interactive agent pane. Flag values such as `--model run` are not subcommands. Interactive startup ignores positional task text, so Orca delivers the task through its existing post-start PTY path. Readiness uses captured native terminal bytes: the configured composer exposes a cursor after bracketed-paste setup, while the initial missing-key connection menu does not. There is no guessed terminal-screen status or fabricated title rule.

Native unrestricted mode is `--permission-mode danger-full-access`. Model launch preferences use `--model`, and changes within the CLI use its `/model` picker. Stable Reasonix reads provider/model choices from user and project TOML configuration; effort support depends on the selected provider and model. Orca therefore does not advertise a fixed model or effort list. See [`internal/boot/reasoning_preflight.go`](https://github.com/esengine/DeepSeek-Reasonix/blob/6dbabcbf7135c56ff5186b0cd36f5cc2725f47b4/internal/boot/reasoning_preflight.go).

## Configuration and credentials

The configuration root honors `REASONIX_HOME`; defaults are `~/.reasonix` on macOS/Linux and `%APPDATA%/reasonix` on Windows, with the native user-profile fallback. `REASONIX_STATE_HOME` separates history from configuration. Orca expands native `~`, `${VAR}` and `${VAR:-default}` forms against the owning host environment before applying its existing absolute-root policy. Native Reasonix also resolves relative overrides against its process cwd; Orca cannot infer that cwd for a global scan and retains its default root for unresolved relative values. Use an absolute or home-based override for managed discovery and hooks. The owning execution host resolves these values through Orca's existing login-shell environment resolver, and local history and search share the resulting projects root. Remote hook discovery returns its validated host-owned configuration root only alongside the optional Reasonix hook capability. A client's environment does not decide where remote settings are written.

Stable source resolves saved provider credentials from the Reasonix-owned global `.env`, with file, auto and legacy keyring migration behavior in [`internal/config/credentials.go`](https://github.com/esengine/DeepSeek-Reasonix/blob/6dbabcbf7135c56ff5186b0cd36f5cc2725f47b4/internal/config/credentials.go). Orca does not copy credentials, implement a Reasonix account manager or claim DeepSeek Build billing authority. The integration does not install credentials, authorize projects or invoke provider login.

## History, search and exact resume

Current native TUI history is `<state-home>/projects/<slug>/sessions-v4/<sessionId>/events.frames`, accompanied by `manifest.json` with codec `reasonix.session.linear/v4` and storage revision 3. A native CLI manifest can lack a Desktop header and cwd. The machine `session list --json` command reads a legacy store; the newly generated current-format session was absent from that list. Orca discovers and reads RX4F history through its existing execution-host filesystem and AI Vault pipelines instead.

RX4F records use big-endian compressed/raw lengths, Zstandard and committed batches. Each frame and content object is capped at 8 MiB; cumulative decompressed framing and referenced content each have a 64 MiB budget. Metadata has separate bounded reads. Required unknown events, invalid hashes, unsupported manifests, symlinks and non-regular files are refused. Reasonix opts into the existing regular-file descriptor guard for local and WSL child reads as well as relay reads: nofollow/nonblocking open and descriptor/path identity checks cover a replacement between stat and open without changing other agents' file policy. Incomplete append tails have no committed authority. The reused DSH Zstandard decoder retains its previous DSH limits and diagnostics.

The projection preserves message identity and order across upserts, retractions and full visible-history replacements. Model-context replacement and compaction do not erase the saved visible chat. A first prompt, preview and message count come from user conversation records; native host context does not become a submitted task or assistant response. Referenced content uses verified lowercase SHA-256 identities, lengths and hashes, never a payload-supplied filesystem path. The transcript iterator releases its execution-host read slot before fetching content objects, preventing limiter exhaustion.

Workspace directory names are lossy slugs. Orca follows the native UTF-8 byte truncation, hash suffix and `.workspace-root` collision marker, and otherwise requires a single matching workspace from the owning host's folder/Git inventory or supplied scope. It never reverse-decodes a slug to invent cwd. Unknown workspace ownership remains visible as history but has no resume command. The decoded editor snapshot is read-only and bounded; it does not open RX4F bytes as editable text.

Exact resume uses `reasonix --resume <sessionId>` with the original validated provider ID and the transcript's `REASONIX_STATE_HOME`. Configuration is not copied into a new home. The existing host-authority admission, process identity, lease and refusal paths remain responsible for launch. A live native workspace lease refuses a second owner rather than creating a replacement session.

Search tracks manifest/header/workspace metadata as well as frame bytes. A changed ownership header reindexes even if the transcript's size and timestamp are unchanged. Invalid metadata clears cached cwd and resume authority while retaining the last good searchable conversation; restored valid metadata is reread. Reasonix bypasses caches that could reuse stale session ownership.

## Canonical status and version skew

Reasonix's native camelCase payload is defined in [`internal/hook/hook.go`](https://github.com/esengine/DeepSeek-Reasonix/blob/6dbabcbf7135c56ff5186b0cd36f5cc2725f47b4/internal/hook/hook.go). Managed hooks cover SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure, PermissionRequest, Stop, StopFailure and SessionEnd. They reuse Orca's POSIX/Windows stdin, endpoint, spool and remote installation paths. The flat native hook schema is preserved, existing user hooks survive install/remove, and malformed settings fail without replacement. Startup and explicit hook controls retain the existing presence and settings gates.

Only the execution host's canonical hook server accepts and publishes status. Native positive turn numbers form a session-bound prompt identity that survives persistence and remote relay. Older turns, late same-turn working events after completion, mismatched sessions, invalid pane/tab identities and stale launch owners cannot advance the accepted revision. UserPromptSubmit supplies explicit accepted input; provider Stop settles the same turn. A native error stays failure across the duplicate legacy Stop and SessionEnd, interruption is cancellation, and ordinary Stop does not invent a successful outcome. Permission requests and the native `ask` tool use the existing waiting/question path. Stable supported hooks do not establish a distinct blocked state.

History and decoded-log requests opt in with optional `includeReasonixHistory` / `decodeReasonixHistory` fields. Hosts advertise `aiVault.reasonix-history.v1` and `agent-session.reasonix-resume.v1`; remote hook preflight advertises `agent-hooks.reasonix.v1` with its configuration root. Old clients retain their closed agent enum and ranking/paging result set because filtering happens before ranking and pagination. New clients remove unsupported filter values before contacting old hosts, and a Reasonix-only unsupported filter returns no results rather than widening the request. Selecting Reasonix on an old host follows the existing unsupported-agent refusal. No stream opcode changed.

## Evidence and limits

A fresh macOS arm64 native 1.39.7 run installed in a task-private prefix printed version/help, opened its PTY composer, accepted harmless tasks and wrote native RX4F/manifest files. A nonce-only localhost provider returned HTTP 401: this produced real native UserPromptSubmit, StopFailure, duplicate Stop and SessionEnd payloads, but no assistant generation or paid/authenticated provider turn. Production scanning, decoding and indexed search read that original file. Hidden Orca CDP checks showed the before/after history, preview, decoded log, search and a guarded exact native resume of the same provider ID.

A separately authorized fixture replay posted captured/source-shaped events to an isolated canonical hook endpoint and verified host revisions, renderer subscription and working, question, answered, permission, failure, interruption and ordinary completion states. It is fixture evidence, not a native successful tool, permission or cancellation run. The native file-only observer never posted to that endpoint, and the QA app did not install provider hooks or alter Reasonix settings/trust.

The new committed native fixtures record their release, source revision and hashes. Inherited fixtures remain intact; vanished prior-worker native logs and authentication evidence were not replayed or claimed. Live Linux, Windows, WSL, SSH, mobile, authenticated assistant generation and native successful tools/approval/cancellation remain unverified. Parent lstat checks refuse stable symlink escapes, but Node does not provide Go's `os.OpenRoot` lifetime guarantee against concurrent parent replacement. No equivalent race-containment claim is made. The existing content-read lifetime reliability gate remains experimental and does not certify those platform or physical-provider gaps.
