## Tabs

Each tab holds one thing: a terminal, an editor buffer, a browser, a diff, a PR. Tabs live inside a **tab group**.

- Drag a tab up-down within a group to reorder.
- Drag a tab onto another group to move it.
- Close every editor file tab in the active worktree with `Cmd+Option+W` on macOS or `Ctrl+Alt+W` on Windows / Linux.
- An active-tab color bar marks which pane is focused.

### Switching tabs

Default chords on **new installs**:

| Action                          | macOS                           | Linux / Windows                 |
| ------------------------------- | ------------------------------- | ------------------------------- |
| Next / previous tab (all types) | `Cmd+Shift+]` / `Cmd+Shift+[`   | `Ctrl+Shift+]` / `Ctrl+Shift+[` |
| Next / previous tab (same type) | `Cmd+Option+]` / `Cmd+Option+[` | `Ctrl+Alt+]` / `Ctrl+Alt+[`     |
| Previous recent tab             | `Ctrl+Tab`                      | `Ctrl+Tab`                      |

Remap under [Settings → Shortcuts](/docs/settings). Existing installs keep customized overrides in `~/.orca/keybindings.json`.

## Split panes

Drag a tab to the edge of a pane to create a split:

- **Right edge** — splits left/right (horizontal split).
- **Bottom edge** — splits top/bottom (vertical split).

Splits nest. You can have an agent terminal on the left, a diff view on the top-right, and a browser tab on the bottom-right — all at once.

Terminal tabs can also split inside the tab. Use the terminal tab menu for **Split terminal right** or **Split terminal down**, or use the split button in the active terminal pane header for a right split.

A tab area showing exactly one pane is capped at the **Single Pane Width** (Settings → Appearance) and centered, unless that pane is a browser page, which always fills the window. While it shows one pane, the next pane that opens — a file, a diff, a browser tab, a new terminal, or a tab an agent opens — opens as a right-hand split beside it rather than as a tab on top of it, and the first pane then fills its half. The exception is a browser tab opening while that pane already shows a browser: it joins as another tab. This happens at any window width, even with the cap turned off, and on remote workspaces as well as local ones. With two panes showing, the split works as a terminal side and a content side: a new terminal opens in the pane showing a terminal, and a file, diff, or browser tab opens in the pane showing content. When both panes show the same kind — two terminals side by side, say — a new tab opens in the pane opposite the focused one. A pane's own **+** button always opens in that pane, and moving tabs between panes by hand is unaffected. With three or more panes, new tabs open in the focused pane as usual; explicit split commands still let you build larger layouts. Reopening a closed tab puts it back where it was, and restoring a saved session — or mirroring a layout from a remote runtime — keeps the arrangement it already had.

## Pinned boundaries

Pane boundaries stay where you put them. Resizing the window doesn't shuffle your layout; boundary positions are saved per worktree.

## Tab groups across worktrees

Each worktree owns its own tab layout. Switching worktrees swaps the entire pane tree — your browser tab, terminal, and diff reappear exactly as you left them.
