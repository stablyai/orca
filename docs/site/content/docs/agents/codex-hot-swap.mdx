---
title: Hot-swap Codex accounts
---

Running multiple Codex accounts to maximize tokens is common. Orca lets you add each account once and switch the active one in a click, with no config editing.

## Add accounts

1. Open [Settings → AI Provider Accounts → Codex](/docs/settings#ai-provider-accounts).
1. Click **Add Account** and finish the Codex sign-in in your browser.
1. Repeat for each account. Every account Orca adds keeps its own sign-in context, so adding one never signs another out.

Accounts are optional: without any, Orca uses your normal Codex login (**System default**).

## Import an existing Codex home

In Codex account settings, choose **Import from home**, then select the home directory containing `auth.json`. Orca copies the login into a new managed account home and activates it on this host. The source credentials stay unchanged. If the source is already an Orca-managed home, normal configuration sync may refresh its `config.toml`. This chooser supports native host homes.

From the CLI, run `orca account add --agent codex --home PATH`. A Windows path imports into the native host; a WSL UNC path selects its own distro. This imports credentials only.

## Choose an account per workspace

Open the workspace context menu, then **Agent accounts**, and choose the Codex or Claude account for that workspace. This also works for folder workspaces. A saved workspace choice takes precedence over the host default for new launches. Clear the workspace choice to inherit the host default again.

Accounts belong to the host running the workspace. A missing or incompatible assigned account requires attention rather than silently launching another account. Existing terminal processes keep the account they started with. Workspace-aware usage readouts use the assigned account and avoid showing another account's quota when its usage is unavailable.

## Swap accounts

Click the Codex chip in the status bar to open the account switcher, or pick an account in Settings. New sessions without a workspace binding use that account, and new chats use that selection. Existing chats retain the account associated with their conversation. Terminal sessions already running keep their original account until restarted.

## Running accounts side by side

In a workspace without an account binding, two Codex terminal sessions can run under different accounts: start one, switch the host account, then start the next. For a bound workspace, change its account before opening the second terminal. Each terminal session keeps the account it launched with. Workspace-bound or History-resumed chats keep their selected account; existing chats keep their conversation account. Usage still counts against each account's own plan; Orca does not pool quota across accounts.

## System default

The **System default** row is your current host Codex login under `~/.codex`. Accounts added in Orca do not rewrite that login; they run in isolated homes. Select System default when you want launches to match a terminal `codex` outside Orca.

## When config edits seem ignored

For managed Codex accounts, Orca mirrors settings from your real `~/.codex/config.toml` into the active runtime home. If that source file is missing, empty (e.g. cloud-sync still downloading), or unreadable, Accounts shows a warning: Codex keeps the **last successfully synced** settings until the source is healthy again. Fix the file at the path named in the banner, then relaunch or reselect the account.

## Rules & gotchas

- Swapping does not re-authenticate; Orca launches new sessions in the selected account's home.
- Existing Codex terminal processes keep their current account until restart. Existing chats retain their conversation account; workspace and History account choices apply when opening a conversation.
- Usage readouts follow the workspace account when one is assigned, otherwise the host selection. A running terminal can still retain an earlier launch account.
- The restart chip preserves the active account at the time of restart.
- Accounts belong to the machine that runs the agent. On a [Remote Orca Server](/docs/remote-servers), add them on that server.

## Other providers

- **Claude Code** accounts are added the same way under **Settings → AI Provider Accounts → Claude**, and switching applies to the next Claude you start.
- **Antigravity** works differently: it switches one shared `agy` login rather than running isolated accounts. See [Antigravity accounts](/docs/agents/antigravity-accounts).
