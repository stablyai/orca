Orca scans the on-disk session transcripts that supported agent CLIs leave behind and lists them in a right-sidebar panel called **Agent Session History**. Pick a past session, click **Resume**, and Orca runs the agent's resume command in a fresh terminal — the recorded working directory and account-aware resume flow, without entering resume flags yourself. Continuing with another account creates a new session, as described below.

## Open the panel

Open the right sidebar and switch to the **Agents** tab. The panel header reads "Agent Session History".

The header shows a count like `12 shown · 47 recent` and a search box. Type to filter by session title, working directory, branch, model, or preview text from the conversation.

## Scope

The scope toggle at the top of the panel decides which sessions appear:

- **Workspace** — sessions from the current workspace or worktree, depending on the active workspace context.
- **Project** — sessions that resolve to the active Orca project.
- **All** — every session Orca found across every agent on this machine.

A session must resume on a compatible workspace on the host that owns its transcript. Resume actions are unavailable when the recording host or target workspace is unavailable. Older connected hosts may need an update.

## View options

The view-options menu (next to the search box) controls which agents are scanned, plus sort and grouping:

- **Agents** — toggle individual CLIs on or off (Claude, Codex, Hermes, Pi, OMP, Prime Agent, Cursor, Gemini, Antigravity, Rovo Dev, Copilot, OpenCode, Grok, OpenClaw, Devin, Droid, Kimi, Muse). Disabled agents are skipped during the scan. Use **Select all** / **Clear** in the Agents header to flip every agent at once — **Clear** leaves none selected so you can turn on only the CLI you care about without unchecking a long list. An empty selection shows **No agents selected** instead of the usual empty-filter message.
- **Sort** — `Last updated` or `Created`.
- **Group** — `Project`, `Folder` (one heading per `cwd`), or `Agent` (one heading per CLI).
- **Hide empty sessions** — drop sessions with zero recorded messages.

## Resume a session

Click a session row to open its details: working directory, branch, model, message count, **First prompt**, and the latest conversation turns. **First prompt** loads the untruncated first user message from the transcript when you expand details (list rows only keep a short preview for search). Use **Copy** on that card to put the full ask on the clipboard — useful for reusing a long prompt without reopening the log. You can also drag an enabled session row into the workspace to resume it. From the row's actions you can:

- **Resume** — opens a new terminal in the session's `cwd` and runs the agent's resume command (e.g. `claude --resume <id>`, `codex resume <id>`, `pi --session <session_file>`, `prime-agent --resume <path>`, `cursor-agent --resume <id>`, `acli rovodev run --restore <id>`). Codex sessions also re-export `CODEX_HOME` when the original session set one.

Pi resumes from the on-disk session file reported by its hooks (`--session <path>`), not from a bare session id. If that file is missing, Resume is unavailable for that row even when a session id exists.

- **Copy resume command** — copies the same shell command to the clipboard for use in an external terminal.
- **Copy session ID** / **Copy log path** — for scripting or attaching transcripts to bug reports.
- **Open log** / **Reveal log** — open the raw transcript file in Orca, or jump to it in your OS file manager.
- **Open cwd** — open the session's working directory as a workspace.

<Callout title="Resume on the recording host">
  Account homes and transcripts belong to the host that runs the agent. Reconnect that host and
  select a compatible workspace before resuming. A local account cannot resume a remote transcript
  by reading a path on your own machine.
</Callout>

## Accounts and independent continuations

For Codex and Claude, **All accounts** shows sessions from the account homes Orca discovers on the selected host. The **Workspace**, **Project**, and **All** scopes still apply. Use the account filter to narrow the list by where a transcript is stored; its storage home is separate from the account last used to resume it.

When you resume from History:

1. Orca prefers the account it last recorded opening that session with.
2. If the workspace explicitly selects another account, Orca asks which account should continue the conversation. The last available account is selected initially.
3. For an older session with no recorded account, Orca asks rather than inferring its previous login from its home directory. An unavailable account must be signed in again or replaced with an available choice.

The choice applies to this continuation only. It does not change the workspace account or the host default. Opening an existing running pane returns to that pane instead of starting a second copy.

### What changing accounts copies

Continuing with another account creates an **independent session with a new session ID** in the selected account's home. Orca carries the conversation history forward, preserves the source transcript, and uses the selected account's sign-in and quota. It does not copy credentials from the source account. Codex history prefixes are materialized into the continuation; Claude companion and file history are copied under the new session identity.

The two transcripts can contain the same earlier messages, but new messages are not synchronized or merged between them. This History resume flow does not use a hardlink to the original transcript or require the old workspace continuation toggle.

For example, continuing session A with account B creates B with A's existing context. Continuing B with account A later creates C with B's context. Opening the original A version instead returns to A's earlier history.

### One History item, multiple versions

Orca records the parent/child relationship and groups related continuations into one History item. Expand **Continuations** to resume a particular version. Unrelated sessions are not grouped merely because they have the same title, and sessions on different hosts stay separate.

The main resume action prefers the most recently opened version recorded by Orca. Copying a resume command or choosing an account does not, by itself, record a successful open. A prepared continuation may appear as **Not opened in Orca** until it is launched. Opening a native chat or creating its terminal records the account; this does not establish that the CLI has completed sign-in or sent a message. Orca does not track every account change made in a separately launched CLI.

If you use **Copy resume command**, account selection can prepare a continuation before the command is copied. Running it outside Orca does not report a successful open back to this History record.

## Where the transcripts come from

Orca reads each agent's own on-disk session store — Codex's `~/.codex/sessions`, Claude's `~/.claude` history, Cursor's session log, OpenCode's legacy session files or `~/.local/share/opencode/opencode.db`, and so on. There's nothing extra to enable; if the CLI writes a transcript, it shows up in the panel after the next scan. Use the **Refresh Session History** button in the header to rescan on demand.
