# 외부 Hermes ACP를 기본 채팅에 연결하기

신뢰한 Hermes ACP 실행기를 등록하면 Orca의 기존 채팅 전송·스트리밍·취소·대화 재개 경로를 사용한다. Hermes 본체, 인증, 모델 선택 정책은 실행기가 관리한다. 이 변경은 기존 터미널 기록을 자동 이관하거나 모든 Hermes 버전에 ACP를 추가하지 않는다.

## 등록

실행 호스트에 사용자 소유 JSON 파일을 만들고 macOS/Linux에서 권한을 `0600`으로 설정한다. 기본 경로는 `~/.config/orca/external-acp.json`이며 `ORCA_EXTERNAL_ACP_CONFIG`의 절대 경로로 바꿀 수 있다. 앱 또는 원격 서버를 재시작해 읽는다.

```json
{
  "version": 1,
  "agents": [
    {
      "agent": "hermes",
      "command": "/absolute/path/to/trusted-hermes-acp-launcher",
      "args": []
    }
  ]
}
```

실행 파일은 표준 입출력 ACP를 제공해야 한다. 호스트·계정·인증은 사용자가 관리하는 실행기 설정에 두며 이 예제에는 포함하지 않는다. 셸 명령문이나 비밀 값을 등록 파일에 넣지 않는다. 등록 프로그램은 실행 호스트의 사용자 권한으로 실행된다.

내장 ACP ID와 중복 ID는 거절한다. 명령·인자가 바뀌면 연결 식별자가 바뀌므로 이전 대화를 다른 서버로 조용히 재개하지 않는다. 잘못된 등록은 외부 에이전트만 비활성화하고 내장 에이전트는 유지한다. macOS/Linux에서는 심볼릭 링크·다른 소유자·그룹/기타 사용자 접근을 거절한다. Windows ACL·reparse-point 보호는 별도 실기 검증이 필요하다.

## 사용과 재개

설정에서 Chat UI를 켜고 저장소의 새 채팅에서 Hermes를 선택한다. 원격 저장소는 소유 서버가 보고하는 에이전트 등록과 채팅 지원 여부를 사용한다. 지원하지 않는 SSH 경로에는 채팅을 제공한다고 표시하지 않는다. 모델과 모드는 ACP 서버의 보고를 기존 채팅 UI에서 보여준다. 실제 응답 모델·실행기 근거를 제공하지 않는 서버에 대해 Orca가 이를 추정하지 않는다.

기존 ACP 대화의 세션 ID와 연결 식별자를 저장해 다시 연다. 이 기능은 임의 Hermes TUI 세션의 기록을 가져오는 별도 어댑터를 포함하지 않는다. 외부 ACP가 없으면 기존 에이전트·터미널 동작이 유지된다.

## 시험

[실제 시험 케이스](../test-cases/hermes-external-acp.md)를 사용한다. `pnpm check:changed --maxWorkers=2`로 변경 관련 형식·린트·타입·시험을 실행한다. 실제 Hermes 연결은 사용자 소유 실행기와 격리된 시험 프로필로 검증하며, 개인 설정·대화·인증 자료를 Git에 넣지 않는다.
