# Bounded Codex execution

`worker-start --execution-policy-file <private-json-file>` uses the existing worker, request ledger and structured-session lifecycle. It currently supports local macOS folder workspaces only. The file is strict schema 1: `sourcePin`, `accountFingerprint` (`codex:<sha256>`), `model`, `effort`, `deadlineAt` (Unix milliseconds) and `access` (`read-only` or `workspace`). The explicit worker model/effort must match. The deadline must be future and within five minutes.

Use an existing undispatched task, or create a child with `--spec` and `--parent`. A prior dispatch, actor reuse, retries, remote placement, setup, forks and terminal fallback are refused. A caller UUID remains the recovery identity; inspect it rather than resending after an uncertain response.

The native child pins ChatGPT login, the default OpenAI Codex endpoint and standard service tier. It replaces inherited launch flags, disables hooks, apps, plugins, canonical multi-agent delegation and web search, removes inherited command environment and disables configured MCP servers through task-local overrides. Thread creation must report disabled MCP runtimes with empty catalogs. It uses an experimental named permission profile with one workspace root, network disabled and explicit temporary-directory denial.

Before the single input is written, the held child must report the admitted included account, model, effort, profile, workspace, sandbox and approval settings. Fresh included allowance and model/effort availability are checked on that connection; the workspace must match the admitted clean Git revision. The first scope admits native macOS executables without wrappers or prefixes and records the real selected path, SHA-256 and version. The final synchronous check revalidates the capture and owner. A second input is refused without reacquisition. Later account or settings drift requests teardown of the exact child.

The deadline timer starts before acquisition and requests owned process teardown. A stop request is not exit proof: root and process-tree observations remain authoritative. `worker-show --full` exports sanitized live facts only while the same owner, fence, generation and dispatch policy binding remain current. Final native-owned receipts persist through close in the existing session record journal. Their readback binds dispatch, policy, fence, generation, runtime ID/PID and startup build digest, compares fresh same-resolver executable/account metadata, and removes the private custody hash. Missing or changed proof stays unknown. Workspace roots are labeled as observed at thread open because Codex's settings notification omits them; the one turn explicitly repeats those roots.

Bounded workers receive only the native `orca_worker_report` reporting tool. Its one-shot publisher checks the original dispatch, process, policy, deadline and generation before delivery through the existing mailbox. Cumulative primary-thread usage, including reasoning tokens, is retained separately from context usage; malformed or missing totals stay unknown. A completed native turn triggers owned teardown, and physical root/tree closure remains distinct from the worker report and owner acceptance.

The runtime capability denotes protocol support, not route qualification, billing verification, successful inference or measured savings. The harness must bind its own source, admission, allowance, build and empirical evidence before promotion. Advisors, remote hosts, other platforms/providers and installed-app adoption require separate qualification.

Bounded input refusal logs name the host admission phase. Fresh quota/catalog requests may wait up to ten seconds, capped by the original execution deadline; unknown capacity still refuses input. For isolated headless qualification, `ORCA_USER_DATA` selects the server profile and `ORCA_USER_DATA_PATH` selects the CLI profile. Verify the same runtime ID in that profile before creating folders or sessions.
