# Bounded Codex execution

`worker-start --execution-policy-file <private-json-file>` uses the existing worker, request ledger and structured-session lifecycle. It currently supports local macOS folder workspaces only. The file is strict schema 1: `sourcePin`, `accountFingerprint` (`codex:<sha256>`), `model`, `effort`, `deadlineAt` (Unix milliseconds) and `access` (`read-only` or `workspace`). The explicit worker model/effort must match. The deadline must be future and within five minutes.

Use an existing undispatched task, or create a child with `--spec` and `--parent`. A prior dispatch, actor reuse, retries, remote placement, setup, forks and terminal fallback are refused. A caller UUID remains the recovery identity; inspect it rather than resending after an uncertain response.

The native child pins ChatGPT login, the default OpenAI Codex endpoint and standard service tier. It replaces inherited launch flags, disables hooks, apps, plugins, canonical multi-agent delegation and web search, removes inherited command environment and disables configured MCP servers through task-local overrides. Bounded children and cold qualification probes disable analytics and every OTel exporter, including custom metrics exporters independent of analytics. They disable memory features, generation and injection without editing the account home. Both require an effective `config/read` response with those memory settings explicitly false; missing or enabled settings refuse qualification/thread creation. Thread overrides repeat the memory exclusions. Thread creation must report disabled MCP runtimes with empty catalogs. It uses an experimental named permission profile with one workspace root, network disabled and explicit temporary-directory denial.

Before the single input is written, the held child must report the admitted included account, model, effort, profile, workspace, sandbox and approval settings. Fresh included allowance and model/effort availability are checked on that connection; the workspace must match the admitted clean Git revision. The first scope admits native macOS executables without wrappers or prefixes and records the real selected path, SHA-256 and version. The final synchronous check revalidates the capture and owner. A second input is refused without reacquisition. Later account or settings drift requests teardown of the exact child.

The deadline timer starts before acquisition and requests owned process teardown. A stop request is not exit proof: root and process-tree observations remain authoritative. `worker-show --full` exports sanitized live facts only while the same owner, fence, generation and dispatch policy binding remain current. Final native-owned receipts persist through close in the existing session record journal. Their readback binds dispatch, policy, fence, generation, runtime ID/PID and startup build digest, compares fresh same-resolver executable/account metadata, and removes the private custody hash. Missing or changed proof stays unknown. Workspace roots are labeled as observed at thread open because Codex's settings notification omits them; the one turn explicitly repeats those roots.

Bounded workers receive only the native `orca_worker_report` reporting tool. Its one-shot publisher checks the original dispatch, process, policy, deadline and generation before delivery through the existing mailbox. Cumulative primary-thread usage, including reasoning tokens, is retained separately from context usage; malformed or missing totals stay unknown. A provider-reported primary-model reroute invalidates bounded execution and stops its child; mixed-model usage stays unknown even after later counters. A completed native turn triggers owned teardown, and physical root/tree closure remains distinct from the worker report and owner acceptance.

The runtime capability denotes protocol support, not route qualification, billing verification, successful inference or measured savings. The harness must bind its own source, admission, allowance, build and empirical evidence before promotion. Advisors, remote hosts, other platforms/providers and installed-app adoption require separate qualification.

`orca chat usage --session <id> --json` reads cumulative primary-thread counters for a held, idle native Codex chat, including an ordinary coordinator without a worker execution policy. It queries that child's actual included account without a cold launch or account switch and returns only its fingerprint and plan. Runtime ID/PID/build, fence, acquisition generation, model, effort and an identity-epoch meter ID bind the reading. The read rejects concurrent input, owner handoff, settings/account changes and malformed or decreasing counters. A primary-model reroute makes usage unverifiable for that acquisition; a later cumulative counter cannot identify its model split. Only a proven new thread before its first input has a zero baseline; resumed threads need a provider counter. Recovery loses the volatile meter and requires a new baseline. A paired CLI must name a session on its target host. These readings exclude auxiliary requests and do not qualify permissions, billing or savings; compare matching meter identities and persist both observations before attributing an interval.

Bounded input refusal logs name the host admission phase. Fresh quota/catalog requests may wait up to ten seconds, capped by the original execution deadline; unknown capacity still refuses input. For isolated headless qualification, `ORCA_USER_DATA` selects the server profile and `ORCA_USER_DATA_PATH` selects the CLI profile. Verify the same runtime ID in that profile before creating folders or sessions.

Bounded creation resolves the account home without preparing it or granting workspace trust in shared configuration. The bounded launch also applies the existing untrusted-project override, preventing Codex’s workspace profile from automatically persisting trust for a Git folder. Bounded Codex launches use the recorded account home without mutable account-home preparation; the native included-account check still runs before input. For isolated headless qualification, pass `--no-agent-hook-sync` to leave existing agent hooks and navigation configuration untouched during startup. It also skips the installed Electron browser helper because older builds reconcile shared hooks during startup; configured external Chromium remains available. This flag does not modify profile preferences or change the normal launch preparation of unrestricted workers.
