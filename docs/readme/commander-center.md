# Commander Center 使用说明

打开 Orca 桌面左侧的 **Commander**。**总览**显示当前运行环境的状态，**记忆**保存账号和当前组织的项目知识。

## 和 Commander 对话

在桌面左侧打开 **Commander**。如果已连接多台执行主机，先用顶部的主机选择器指定目标主机；默认使用本机。点击 **与 Commander 对话**，然后直接输入目标。例如「看看 API 和 iOS 项目里哪些任务被卡住了，把需要我决定的事列出来」。在 Android 手机或 iPhone 上打开同一台桌面的 Commander Center，也可点同一个按钮继续对话。手机连了多台桌面时，选择运行这段对话的那一台。

第一次打开时，Orca 会在当前主机和配置下创建专用的 Commander bot，使用已配置的兼容聊天 agent。主机需要启用 Bots，并已配置可用的 provider。之后打开同一入口会回到它的 Home Chat。对话保存在执行主机上。账号的跨设备 Markdown 记忆、项目指南及访问授权仍在 **记忆** 中管理。

打开入口本身不会发送消息。你发送目标、Commander 处理 worker 回报，以及 worker 执行任务时，对应的模型可能产生用量。读取运行状态本身无需调用模型。Commander 可以先合并任务计数和待决事项，再按需要查看单个任务。它通过 Orca 原有的任务、消息和审批机制推进工作。运行中的 Orca agent 也可以用 `orca bot list` 查到这个 bot 的实际名字，再用 `orca orchestration send --to bot:<名字>` 给它发消息。

## 换主机继续同一个目标

在第一台电脑打开 **Commander → 交接 → 新建交接**，填写目标、进展和下一步。也可以点 **使用最近的对话**，从这台主机的 Commander 主对话带入最近一轮的简短预览。确认内容后保存。交接作为带修订号的 Markdown 页面存入当前账号和组织的记忆。

在另一台电脑登录同一个 Orca 账号，选择同一组织，打开 **Commander → 交接**，选中目标并点击 **在 Commander 中继续**。核对新主机的聊天草稿后发送。两台桌面需连接同一套已部署的 Commander Memory 账号服务。交接保存成功后，即使原主机已关机，仍可从另一台主机读取。Android 和 iOS 客户端通过已启用记忆共享的配对桌面访问交接。Linux、macOS 和 Windows 桌面使用同一个 Commander 入口。交接依赖账号和组织，代码仓库的本机路径可以不同。

交接按最近更新时间排列，每次读取 50 条。可以选择项目，也可以输入记得的目标、进展或下一步，例如「核对退款金额」。搜索覆盖当前范围内的全部交接。配对手机连接支持搜索的桌面后也可以使用这两个条件。桌面、手机和账号记忆服务升级到 Commander .9 后，可以在不下载整个记忆库的情况下查找交接。

交接记录包含你保存的文字。聊天全文、尚未保存的对话、未提交的文件和运行中的进程仍在来源主机。涉及代码的目标，可以在进展中记下仓库、分支和提交号，方便新主机检出对应版本。

## Agent 中断后，在另一台电脑接手

在运行 agent 的桌面上，登录账号，选择组织，打开 **Commander → 记忆 → 自动保存 Agent 交接记录**。开启后，Orca 会为本机已登记 Git 工作树里的 Codex 和 Claude 原生聊天记录简短的回合进展。回合摘录来自聊天中输入和回复的文字，各最多 280 个 UTF-16 代码单元。开启前请考虑这些摘录中可能包含的项目内容。每台来源设备分别授权。记忆页显示上次保存时间或同步延迟。

在另一台桌面登录同一账号和组织，连接同一个记忆服务，打开 **Commander → 交接**。选择记录，指定已检出的对应项目和工作树，从新的 Codex 或 Claude 聊天接手，或点 **在 Commander 中继续**。先核对聊天草稿中的进展、下一步和 Git 状态，再发送。手机可通过已授权的配对桌面查看记录并在 Commander 聊天中继续。

新 worker 的草稿包含交接里记录的目标、进展、下一步和目标工作树的分支、提交号，还会带入账号及该项目下由人最后编辑的指南。指南超出草稿预算时，草稿会提示你去记忆中查看其余内容。如果打开聊天期间交接已经更新，先查看最新修订后再继续。

Git 分支、提交号和工作树状态反映来源主机上一次成功取样的情况。记录中显示有本地改动时，补丁或未跟踪文件仍需从来源主机取回。未完成的回合可能只有用户请求和最后一个已知状态；恢复时先核对目的工作树，再重做可能有副作用的操作。原始聊天全文、终端输出和代码差异不在这份交接记录里。直接在终端或 WSL 里独立启动的会话不在本机原生聊天的自动记录范围内。

## 在几百个 agent 中定位阻塞

在 **Commander → 待决事项** 中，相同问题的多个请求会显示在同一组。展开组并选择具体项目和会话，在该会话原有的审批界面答复。相同的显示文字可能对应不同主机、目录和操作，界面保留各自的审批上下文。

项目表把阻塞数最多的项目排在前面。每行给出阻塞、等待、工作中及总数，并显示状态比例。可以按项目名搜索。点击项目的非零阻塞、等待或工作中数量，直接查看该项目对应状态的 agent。键盘聚焦数量后按 Enter 也能进入。点项目总数可回到全部状态，再点卡片进入工作上下文。下方沿用 Orca 的虚拟列表，仅渲染可视范围附近的卡片。

总览依赖当前 Orca 能读取的运行环境。换电脑后，先在记忆中查看最近成功保存的项目记录，再连接执行主机查看实时状态。

## 让 Commander 复用项目里的常用答复

在桌面或已授权的配对手机上，打开 **Commander → 记忆**。先打开常用答复的开关，再点 **新增常用答复**。该开关默认关闭，对当前账号和组织的所有项目生效。关掉后，新的查询和对已答问题的重试都会暂停自动答复，保存的规则与决策记录仍可查看。选择项目，填写问题原文和答案，然后保存。例如，移动端项目可以把「发布说明用什么语言？」的答复设为「用中文写，保留英文 API 名称」。另一台电脑连接同一记忆服务、登录同一账号并选择同一组织后，也能查看或修改这条规则。

Commander 或已接入记忆工具的 agent 可以在打断你之前查询项目规则。问题文字和标点一致且只有一条有效规则时，服务返回你保存的答案。这次查询无需调用模型。没有匹配或有多条匹配时，agent 会得到原因，应把问题交给你。可以在桌面记忆页选择 **决策**，查看提问者、问题、返回的答案和所用规则版本。修改或删除规则会影响后续各次提问；同一次提问重试会取回原结果。脚本执行和工具权限继续由原工具的审批流程处理。

本机已登录的 Commander Home 可以为该桌面已登记的项目查询常用答复。在打开功能前已经运行的 Home 会话可能需要重新启动。会话凭据随当前主机、账号、组织和本次启动生效，最长八小时。外部客户端可以用项目授权接入。两种入口都遵循同一个账号开关。

## 让记忆跟随账号

安装包默认使用官方 Orca 登录服务。本分支提供的记忆后端需要由账号服务运营者部署。两台设备连接同一个部署了该后端的 Orca 账号服务，登录同一账号并选择同一组织。打开 **记忆**，即可读取先前设备上的页面。页面可以属于具体项目或整个账号，每次保存产生一个版本。两个设备同时修改时，界面保留草稿，要求比较新版本后再保存。删除页面保留历史。项目选择器也列出尚未写过记忆的仓库，方便直接写第一条项目指南。在「总览」和「记忆」之间切换会保留当前编辑草稿。页面清单按最近修订排列，版本历史可以按需展开并加载更早的版本。

桌面和配对手机的记忆列表每页显示 50 条摘要。打开一条记录可查看全文和修订历史。桌面搜索会查找当前项目和筛选范围内所有页面的标题、正文和作者，包括其他页上的记录。请同时升级桌面和记忆服务以启用服务端分页。已配对的手机会通过更新后的桌面使用同一索引。

- 用 **指南** 记录长期约束，例如“改动 API 后先运行契约测试”。派发启用 Commander 策略的任务时，Orca 会把适用的人类指南放入 worker 的任务说明。
- 用 **决定** 记录一次取舍及其理由。版本显示人、Commander 或 agent 的身份；页面之间可建立链接。
- 在需要记录进度的机器开启 **记录本设备项目进度**。只要桌面 Orca 正在运行，后台会定期将变化后的工作摘要写入账号，包括项目、任务、agent 和阻塞原因。摘要按状态保留总数和有限的条目，适合交接。完整的代码文件和聊天记录另行管理。通过 Commander 为该项目启动新 worker 时，最近一次自动检查点的时间和进度摘录会随人工指南进入任务说明。摘录最多 2 KiB，指南优先，两者合计最多 8 KiB。
- 要让外部助手接手，在项目记忆页导出限时访问文件，并以 `--memory-grant <文件>` 启动 Commander MCP。助手能查找检查点、指南及决策，也能以自己的身份提交修订。记忆以 Markdown 展示，服务使用 SQLite 保存页面与修订。

[账号服务部署及认证](../../cloud/apps/commander-memory/README.md) · [助手接入](./commander-mcp.md)

## 在 iPhone 上使用 Commander

先在桌面端的 **设置 → 移动设备** 配对 iPhone。如果手机使用桌面端提供的主机页面，打开已更新的桌面，点 **… → Commander Center** 就能查看该桌面上的项目。用本分支构建的 iOS 客户端还会在首页显示独立的 Commander 标签，可以一起看多台桌面。点需要处理的项目，再点 agent 即可打开对应会话。失去连接的桌面会标明实时状态不可用。

手机上的 **记忆** 通过已配对的桌面访问当前账号和组织。先在桌面端的 **Commander → 记忆** 开启向已配对手机共享，再在手机上选择这台桌面。手机可编辑 Markdown 指南、决定和笔记，也能查看历史版本和修改者。记忆服务的部署要求与桌面端相同。

[手机端构建与配对说明](../../mobile/README.md)

## 从另一台电脑恢复 Git 工作

Linux 的 deb 和 rpm 安装包提供 `orca-commander-handoff` 命令，使用 Orca 自带的运行时。仓库里的 `pnpm build:linux` 会把这个命令加入 Linux 软件包。准备一份 JSON 交接记录，例如 `{"goal":"发布 API","next":"验证 SDK 测试"}`，然后在原电脑的项目目录运行：

```sh
orca-commander-handoff save release progress.json --include-tracked-edits
orca-commander-handoff publish release origin --include-tracked-edits
```

发布会把交接分支推到指定 Git 远程，包括保存时的基线提交及其 Git 历史，即使它们尚未推送到项目的普通分支。已跟踪文件的改动在显式选择后保存为补丁。未跟踪文件、被忽略且未跟踪的文件和子模块内部改动不会进入补丁。

在新电脑克隆同一仓库后，运行 `orca-commander-handoff restore release origin`。这一步只取回记录与 Git 对象。用 `git switch --detach <commit>` 切换到返回的基线提交；如果记录有补丁，在干净的工作区运行 `orca-commander-handoff apply release` 将它应用到暂存区。旧版记录仍可读取；如果旧版记录对应的基线没有推送过，可从保有该提交的电脑用新命令重新发布。

## 选择模型、推理强度和代码上下文

在记忆中创建标题为 `Worker model routing` 的指南，按任务类别设置希望使用的模型、effort 和理由。模型及推理强度需要当前 agent 和运行环境支持。显式提供的启动参数优先；多个等优先级规则冲突时会提示处理。在项目内导出 Commander 授权文件，设置 `ORCA_COMMANDER_MEMORY_GRANT_FILE`，再以 `orca orchestration worker-start --commander-project <项目标识> --commander-task-kind <类别>` 加上正常的 worker 启动参数。记录中的选择表示计划派发，实际是否启动以 Orca 的启动回执为准。使用者可以从记录核对策略；实际节省的 token 取决于模型、任务和执行结果。

例如，下面的指南会给 Codex 的 README 更新选择低推理强度。模型名称应与当前提供方支持的名称一致。

```json
{
  "version": 1,
  "routes": [
    {
      "agent": "codex",
      "taskKind": "docs",
      "containsAny": ["readme"],
      "model": "gpt-5.4-mini",
      "effort": "low",
      "reason": "文档修改只需要校对文字并检查链接。"
    }
  ]
}
```

从仓库根目录运行以下命令可以查看已跟踪 JavaScript 和 TypeScript 文件的相对导入关系。用 `--scope` 缩小到当前任务涉及的目录，或加上 `--json` 给另一个程序读取。助手也可以调用 MCP 的 `commander_code_graph`。结果附带来源文件、引用行号和扫描覆盖信息。

```sh
node /path/to/orca/scripts/commander-code-graph.mjs --scope src --max-files 80
```
