Workspace cleanup redesign mockups

Five broad directions for the branch's old-workspace cleanup flow. These are static HTML mockups that keep Orca's quiet token system while exploring different selection, review, and destructive-action models.

OSS read: VS Code bulk edit preview and tree/list behavior, plus Superset workspace multi-select, context menu, and delete confirmation patterns.

1

Triage queue with inspector

Best default candidate: selection stays central, risk detail moves to a stable inspector, and the destructive action remains gated behind the selected count.

Broad OSS advice: use VS Code-style list focus plus Superset-style contextual details instead of expanding every row.

Preview before delete

Treat cleanup like a bulk edit: users check rows on the left and inspect a manifest of filesystem, state, and branch effects before applying.

Broad OSS advice: VS Code's bulk edit preview makes irreversible batch operations feel auditable before the final action.

3

Guided cleanup wizard

A more conservative flow for users who fear losing work. It separates discovery, selection, and final confirmation into visible stages.

Broad OSS advice: separate safe navigation from destructive confirmation; make the back-out path quiet and obvious.

Dense table for power users

Keeps the current modal shape but shifts from card-like rows to a compact, sortable table with persistent columns for age, git safety, context, and action.

Broad OSS advice: VS Code and terminal tools favor dense rows when the user is comparing many local resources.

5

Workspace inbox

Frames stale workspaces as an inbox to process: keep, snooze, open, or remove. This is strongest if cleanup becomes a recurring maintenance habit.

Broad OSS advice: Superset's workspace sidebar treats workspaces as an attention queue, with hover actions and multi-selection captured at action time.
