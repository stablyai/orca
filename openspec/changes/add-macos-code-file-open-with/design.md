# Design

## Context

动机见 [proposal.md](proposal.md)。现有系统请求经主进程队列和已有 IPC 进入本机独立浮动工作区；语言识别、文件读写、二进制提示及 50 MiB 文本限制均已存在。主进程与安装包目前只接受 md、markdown、mdx、csv、tsv。静态语言扩展名覆盖由 TS 映射和 Monaco JSON 元数据共同决定。

## Goals / Non-Goals

**Goals:** 使用已有文件打开链路，扩展 macOS 的系统文件处理能力，并保持启动入口与用户文件之间的边界。

**Non-Goals:** 不新增项目归属推断、设置开关、语言实现、公开 IPC、文件编码转换或 Windows/Linux 关联。不声明通用文件类型或星号关联。

## Decisions

### 文件关联复用语言数据

将现有 TS 语言后缀覆盖映射抽为 JSON，语言识别照常使用该映射；CJS 打包器合并该映射、现有 Monaco 后缀及 txt、text、log、lock 后去重，并保留已有 Markdown/CSV/TSV 声明。每个后缀仍单独声明 Editor/Alternate，复用应用图标。这样 CJS 无需执行 TS，打包声明也能覆盖既有语言支持。相比另建手工语言列表，该方案复用现有事实源。

### 明确启动参数与文件路径的输入契约

完整进程参数先跳过可执行文件，并按 Electron 的 process.defaultApp 跳过应用入口；用户文件列表不跳过首项。绝对路径、file URL、路径归一化、去重及队列上限继续沿用既有逻辑。macOS 解除文件后缀限制，使通过“其他…”指定的本地普通文件也能进入现有编辑器；Windows/Linux 保持现有后缀校验。

### 复用独立文件编辑与可观测性

FileDocument、旧 IPC 名称和独立文件打开函数保持兼容。本地文件固定使用本机浮动工作区，沿用 user-file 访问声明、原路径保存和标签去重。无新增远程调用、持久化模式、异步通道或 OTel SDK；otel-spec 审查结论为沿用现有 [os-open] 队列丢弃与解析失败日志，不新增文件内容、路径或高基数属性埋点。

### 约定验证接缝

采用已批准计划中的参数接收、磁盘文件解析、真实打包产物和现有 Playwright CDP 系统打开文件测试接缝。语言数据抽取运行既有语言识别测试。按每个接缝保留 RED/GREEN 证据，不增加镜像内部实现的测试。

### 冷启动时保留绝对文件读取结果

隐藏 Electron 回归发现：首次读取返回后，浮动工作区目录从 null 初始化为本机 home，通用目录变更保护丢弃该结果，编辑器持续显示 Loading。独立文件使用绝对路径与 user-file 访问声明，不依赖面板工作目录。因此在既有文件操作归属函数中仅排除浮动工作区的目录变更校验；文件身份、主机归属、连接代次和项目目录变更校验仍保留。用失败回归和真实冷启动保存验证该边界。

## Risks / Trade-offs

- 仓库根目录门禁尚未允许 OpenSpec → 仅将用户已授权初始化的 openspec 根目录加入现有 reviewed 清单，并用实际 Git 树测试验证；其他新增根目录仍拒绝。
- 放开 js 等后缀会误收程序入口 → 在完整参数边界显式剔除入口，纯路径列表单独处理，并验证普通启动没有额外文档。
- Finder 按系统文件类型匹配无扩展名文件 → 常见后缀直接声明，其他文本可由用户通过“其他…”选择；不声明 public.data 或星号。
- 文本后缀也可能包含二进制或超大内容 → 使用现有编辑器检查和提示，不执行所选脚本或改写原始内容。
- Electron 验收影响用户桌面 → 使用隔离合成目录与用户数据，设置 ORCA_BACKGROUND_LAUNCH=1，窗口隐藏并用 CDP 断言；可见 Finder 菜单人工验收。

## Migration Plan

无需数据迁移。功能由新 macOS 安装包的 Info.plist 生效，测试使用独立临时包及独立 bundle ID；不覆盖当前安装版或主动更改默认应用。回退代码与安装包即可撤销新增声明。
