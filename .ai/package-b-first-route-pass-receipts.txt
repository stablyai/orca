DEFECT FOUND AND FIXED THIS RUN (b64a547b1f)

  Certifying a never-yet-observed route was reachable only through a call that
  FAILED. requireRealLaunch compared the claim against the persisted receipt,
  which holds the requested alias until the provider is observed; the observation
  itself only runs inside the LATER gate. So:
    claim the observed route -> identity_mismatch, and no observation ever runs
    claim the alias          -> observation runs as a side effect, then the call
                                fails on the comparison
  The observation existed and nothing could ask for it without being rejected.
  The guard now prefers what the provider was observed running and falls back to
  the receipt; the alias is still refused. Regression test in
  certification-admission.test.ts covers both halves.

  Both live runs below were done BEFORE this fix, so both show the two-call
  bootstrap in the receipts above; the fix removes the failing first call.
